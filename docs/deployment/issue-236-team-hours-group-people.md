# Team hours: selected group people

Deploy application code and compiled assets together after the #235 overview. No migration, backfill, persistent cache, new indexes, or temporary nullability is introduced. Rollback needs no schema change.

Calvin confirmed on October 20, 2026 that this selected-group report loads the complete eligible roster once per event/group/date range: Hired members, including those without assignments at zero hours, plus members of any status with assignments in the chosen range. Non-Hired members whose assignments are all outside the range are excluded. Assignment presence qualifies even when breaks reduce hours to zero; changing away from Hired never removes assigned hours from people, group, or event totals. This decision supersedes the earlier all-members rule. This narrow people-list pagination exception is recorded in AGENTS.md. Scheduled hours use the existing grouped SQL calculation and shift start day, with a free inclusive date range or both dates blank for all scheduled days. The group's cards sum the same people rows. Approved and Unapproved remain unavailable until #205, and no pay rates or money are selected or returned.

The locked desktop, phone people, and error frames guide the Group picker, Back to All groups, date fields, group totals, and people table. There is no No group bucket (#234/#242). Names and row chevrons open the existing event Team member page in the same tab only with team.view; report-only users see plain names. Group/date filters live in the report query string and Inertia history so browser Back restores them. The phone people list uses the shared DataTable summary mobile layout. A failed people load shows the named error and Retry link while retaining group totals already known for that same range. By shift (#238), export (#239), worked hours (#205), per-person shift breakdowns (replaced by the member-page link), and other report phone screens (#240) remain out of scope.

The new GET endpoint requires team.hours_report.view (admins also pass), scopes the selected group to the current event, and remains readable on locked events. Each successful response stays in memory only for the page visit; failed responses can be retried and are never cached. External edits do not automatically refresh already loaded report results, so separately fetched overview and detail snapshots can differ after concurrent changes.
